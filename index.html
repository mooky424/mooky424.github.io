Haskell

Released in 1990, Haskell is a purely functional, non-strict programming language with strong, static typing. Commonly used in applications where reliability and correctness are critical, such as academia, finance, and embedded systems.

How Haskell functions, and how you solve problems with it

Pure, non-strict, and statically typed

A Haskell program is a set of equations. Three commitments decide what those equations mean when they run.

  • Purely functional. Functions behave like mathematical functions, which is the lambda-calculus basis. The same arguments always produce the same result. There are no statements that mutate a local or global variable, and a pure function cannot read the clock or a random generator. Every computation is a function with no side effect. Effects that a whole program does need, such as printing, are values of type IO.
  • Non-strict. An expression is evaluated only when its value is needed. That is what lets a program name an infinite structure and then use a finite piece of it. take 5 [1..] builds five numbers. A function that never looks at an undefined argument can still return a useful result.
  • Strong, static typing. Every expression has a type, and that type is fixed at compile time. If the types in a function application do not match, GHC rejects the program before it runs. Types are also a way of saying how the program is built. You do not have to write every signature: inference fills them in by unifying types in both directions. Writing a signature anyway documents the equation, and :t in GHCi will print the one the compiler inferred.

Functions instead of instructions

That is the mindset for solving a problem. Describe what a value is, and let the evaluator demand the pieces it needs. There is no loop variable to update and no mutable accumulator. Recursion, map, filter, and folds take that place.

The practical payoff is a small semantic gap. The equation you would write on paper and the equation in the file are close, so the program stays modifiable. That shows up where reliability matters: web apps, tools, and systems; mathematical modeling and financial analytics; embedded systems and IoT; academic research; concurrent and parallel programming; and formal verification. GHC also talks to other languages through a foreign interface, so a Haskell core can sit next to C.

Ecosystem

Source files use the extension .hs. The everyday tools around those equations are:

  • GHC, the Glasgow Haskell Compiler, is the flagship compiler. ghc filename.hs compiles a file. On Windows the result is filename.exe. On Unix it is ./filename.
  • GHCi is the interactive debugger and interpreter. :t asks for a type, :reload picks up a save.
  • Stack is the project tool: it pins a compiler version and builds a package. stack ghci and stack build are the everyday commands.
  • Packages live on Hackage. The Prelude is the module every program imports for you. Data.List, Data.Char, Data.Map, and Data.Set are the next ones people reach for, and a project can define its own modules.

Where Haskell is the harder choice

  • Less mainstream. Hiring, examples, and production stories are thinner than for the languages most teams already use.
  • Lazy evaluation can bottleneck performance. Work can pile up unevaluated and hold memory until something demands the number. Predicting cost means knowing what is demanded.
  • Fewer libraries than Python or Java. Hackage is real, and it is not those ecosystems.
  • A steep curve for someone whose habits come from another paradigm: guards, monads, and type-class errors are the wall after the first pleasant functions.

The type-class ladder

A class names an ability a type can have. Eq, Ord, and Num are the everyday ones on Int and Char: equality, order, and arithmetic. Functor, Applicative, and Monad are the other kind. Each one needs a type constructor such as the list constructor or Maybe, and Int has nothing for fmap to change.

Monad

class Applicative m => Monad m where
  return :: a -> m a
  (>>=)  :: m a -> (a -> m b) -> m b

Maybe and IO use return and >>=.

Monads

add 2 5 is 7. A function that wants an Int can take that 7. Just 3 is not an Int. Its type is Maybe Int, the number or Nothing. putStrLn "hi" is not a string. It is a print that has not run yet. The next function still wants the plain value: the 3, or the () a print produces when it finishes.

return wraps a plain value so the chain can start. For Maybe, return 3 is Just 3. >>= takes the wrapper off and gives what was inside to the next function. That function has to return the same kind of wrapper: another Maybe, or another IO. Nothing has no number inside, so the next function is not called. An equation cannot print or change a variable on the side, so failure and printing are values of their own. That is why main has type IO (), and why add 2 5 stays an ordinary sum.

Maybe can stop

next :: Int -> Maybe Int
next x = if x > 2 then Just (x * 10) else Nothing

return for Maybe is Just. Just 3 >>= next opens the Just, and next sees 3, so it returns Just 30. Just 1 >>= next opens the Just as well, and next returns Nothing. A starting Nothing never calls next.

The next step sees the value

<*> applies a function that is already sitting in the context. >>= builds the next context from the value it just unwrapped. next looks at the number and chooses Just or Nothing.

IO is the same pair of methods

do writes a chain of >>= as steps.

main = do
  putStrLn "The sum of the two numbers is:"
  print (add 2 5)

-- the same steps
putStrLn "The sum of the two numbers is:"
  >>= \_ -> print (add 2 5)

putStrLn produces IO (). The lambda ignores that () and runs print. add 2 5 stays a pure equation. The type of main is IO (), so the printing stays in the type and the equations around it stay replaceable by their definitions.

Three laws

f >=> g is the function that runs f, then binds g. Any monad has to obey these three equations, which is what lets a chain be replaced by the definitions of its steps:

return >=> mf    = mf                 -- left identity
mf >=> return    = mf                 -- right identity
(f >=> g) >=> h  = f >=> (g >=> h)    -- associativity

On next, left identity says return 3 >>= next equals next 3. Right identity says Just 3 >>= return equals Just 3. Associativity says the grouping does not matter: bind next and then step, where step y = Just (y + 1), or bind the combined function.

Declarations on the left, behavior on the right

add :: Integer -> Integer -> Integer   -- declaration: the type

  x + y                                -- indent continues it; no semicolon

On a pair, fst :: (a, b) -> a and snd :: (a, b) -> b. curry :: ((a, b) -> c) -> a -> b -> c and uncurry :: (a -> b -> c) -> (a, b) -> c switch between a function on a pair and a curried function.

What the design buys

  • Referential transparency. A pure name can be replaced by its definition. Monads keep effects in the type, so the equations around them stay transparent.
  • Polymorphism. One function can be reused at many types.
  • Concurrency. Effects are explicit, so GHC can schedule work on lightweight threads. Garbage collection is built in, and the collector can run in parallel.

Five ways to write a function

A function can be passed, returned, or stored. Work runs only when something demands the result, so there is no loop and no mutable variable.

Pattern matching

sumList :: [Int] -> Int
sumList []     = 0
sumList (x:xs) = x + sumList xs

The (x:xs) equation peels one element at a time until [] returns 0.

ghci> sumList [1,2,3,4]
10
it :: Int

Guards

factorial :: Integer -> Integer
factorial n
  | n <= 1    = 1
  | otherwise = n * factorial (n - 1)

Guards run from top to bottom. 5 fails n <= 1, so otherwise multiplies down to 1.

ghci> factorial 5
120
it :: Integer

Where clause

quadraticRoots :: Float -> Float -> Float -> (Float, Float)
quadraticRoots a b c = (root1, root2)
  where
    root1 = (-b + sqrt discriminant) / (2 * a)
    root2 = (-b - sqrt discriminant) / (2 * a)
    discriminant = b * b - 4 * a * c

For 1, -3, 2 the discriminant is 1. The roots are 2 and 1. root1 and root2 are local to this equation.

ghci> quadraticRoots 1 -3 2
(2.0,1.0)
it :: (Float, Float)

Recursion instead of iteration

fibonacci :: Int -> Int
fibonacci 0 = 0
fibonacci 1 = 1
fibonacci n = fibonacci (n - 1) + fibonacci (n - 2)

fibonacci 6 is fibonacci 5 plus fibonacci 4. The two calls repeat work a loop would save.

ghci> fibonacci 6
8
it :: Int

Lambda

incrementList :: [Int] -> [Int]
incrementList = map (\x -> x + 1)

The lambda is an unnamed function passed straight to map.

ghci> incrementList [1,2,3]
[2,3,4]
it :: [Int]

Returning a function

add looks like two arguments. The type Integer -> Integer -> Integer is Integer -> (Integer -> Integer): one argument comes back as a function waiting for the next. curry and uncurry switch between this form and a function on a pair.

Quicksort by list comprehension

quicksort :: Ord a => [a] -> [a]
quicksort [] = []
quicksort (x:xs) =
  quicksort [a | a <- xs, a <= x]
  ++ [x] ++
  quicksort [a | a <- xs, a > x]

The imperative sort walks indexes and swaps cells. This one names the pivot, the values that belong before it, and the values that belong after it. Each side is the same function on a shorter list. The empty list is the base case.

The first pivot is 4. Smaller or equal: [1,3,2]. Larger: []. Each side is sorted by the same equation.

ghci> quicksort [4,1,3,2]
[1,2,3,4]
it :: [Int]

Function composition

eveno :: Int -> Bool
noto  :: Bool -> String

eveno x = if x `rem` 2 == 0
            then True
            else False

noto x = if x == True
           then "This is an even Number"
           else "This is an ODD number"

main = do
  putStrLn "Example of Haskell Function composition"
  print ((noto . eveno) 16)

eveno 16 is True. noto turns that into the even-number string. The dot applies eveno first.

ghci> (noto . eveno) 16
"This is an even Number"
it :: String

A zipper points at one place

The focus is the cell you edit. The rest is the path back, so one change does not start over from the root. On a list, the left side is stored reversed and the nearest neighbor is the head.

type Zipper a = ([a], a, [a])

goRight :: Zipper a -> Zipper a
goRight (ls, f, r:rs) = (f:ls, r, rs)

goLeft :: Zipper a -> Zipper a
goLeft (l:ls, f, rs) = (ls, l, f:rs)

replace :: a -> Zipper a -> Zipper a
replace x (ls, _, rs) = (ls, x, rs)

The focus starts on 1.

goRight and goLeft do not cover an empty side.
